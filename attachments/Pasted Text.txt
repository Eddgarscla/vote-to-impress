Quiero hacer ahora una actualización importante de VOTE TO IMPRESS. NO reconstruyas la aplicación desde cero y NO elimines ni rompas la autenticación, base de datos, perfiles, posts, follows, likes, comentarios, challenges ni el resto de la arquitectura que ya funciona. Trabaja sobre el proyecto existente.

Voy a proporcionarte imágenes de referencia de mi logo, personajes y estética. ÚSALAS COMO REFERENCIA ARTÍSTICA Y DE DIRECCIÓN VISUAL, no como imágenes que debas copiar literalmente ni reutilizar directamente. Quiero que la identidad final sea ORIGINAL y propia de Vote to Impress.

1. IDENTIDAD VISUAL

Quiero abandonar completamente la estética beige, plana y genérica de red social.

Vote to Impress debe sentirse como una mezcla de:

* 3D fashion/avatar game
* high-fashion editorial
* glamour
* cute digital world
* camp
* futuristic fashion
* Bratz-inspired attitude
* Monster High-inspired dark/cute energy
* videojuegos de moda y competición

NO quiero simplemente “fondo negro + botones rosas”. Quiero una identidad visual completa: personajes 3D estilizados, materiales glossy, iluminación de estudio, escenarios temáticos, elementos decorativos, tarjetas de competición, efectos de lujo, siluetas de moda, detalles coleccionables y una interfaz que parezca parte de un universo de fashion game.

El logo que te proporcionaré debe ser una referencia principal para construir la identidad de marca, pero puedes desarrollar una estética propia alrededor de él.

La interfaz debe funcionar perfectamente tanto en móvil como en desktop.

2. LANDING / PRIMERA VISITA

Un usuario nuevo NUNCA debe entrar directamente a un feed aparentemente lleno de usuarios reales.

Primera visita:
VOTE TO IMPRESS
Logo/branding
Presentación visual de la plataforma
CREATE ACCOUNT
SIGN IN

Después de registrarse, el usuario entra a su propia experiencia.

Si todavía no existen publicaciones reales, NO inventes actividad comunitaria para hacer parecer que existen usuarios reales.

Mostrar un empty state elegante, por ejemplo:
“Your fashion era starts here.”
“Create your first look and make an impression.”

El contenido demo debe estar claramente separado del contenido real de usuarios.

3. SISTEMA DE CHALLENGES

Quiero implementar un sistema real de competición semanal y mensual.

Cada semana debe existir un Weekly Challenge con:

* tema
* descripción
* fecha/hora de inicio
* fecha/hora de cierre
* participantes
* submissions
* periodo de votación
* ranking final

El sistema debe cerrar automáticamente la competición cuando termine el periodo establecido.

NO quiero tener que contar votos manualmente cada semana.

El backend debe calcular automáticamente:

* votos válidos
* puntuaciones
* posiciones
* Top 3
* ganador
* Impress Points
* progreso de niveles
* estadísticas del challenge

Cuando termine una competición, el sistema debe publicar automáticamente el resultado.

4. VOTOS VS LIKES

SEPARAR completamente:

❤️ LIKE = interacción social normal. Puede utilizarse libremente.

🏆 COMPETITIVE VOTE = voto oficial de una competición.

Un usuario NO debe poder votar ilimitadamente dentro de un challenge.

Implementar un sistema limitado de votos competitivos por competición. Como primera configuración propongo 10 votos competitivos por usuario y challenge.

Reglas:

* un usuario puede utilizar cada voto para un participante diferente;
* no puede votar dos veces al mismo participante en el mismo challenge;
* no puede votar su propio submission;
* los votos deben estar asociados a la cuenta autenticada;
* evitar votos duplicados;
* registrar los votos de forma segura en la base de datos.

IMPORTANTE: no quiero que el feed normal permita convertir el scroll en una máquina de votar a todo el mundo. El voto competitivo debe pertenecer al sistema de competición, no al Like normal.

5. RESULTADOS OCULTOS

Durante la competición NO mostrar:

* score
* número de votos
* posición
* ranking provisional

El objetivo es evitar que los participantes sepan quién va ganando y evitar comportamiento estratégico.

Los resultados deben permanecer privados hasta que termine oficialmente el challenge.

Cuando finalice:
automáticamente publicar:

🥇 1st Place
🥈 2nd Place
🥉 3rd Place

y mostrar sus puntuaciones/resultados.

El sistema debe conservar internamente todos los datos necesarios para auditoría y estadísticas aunque el público no pueda verlos durante la competición.

6. PUNTOS Y NIVELES

Crear un sistema de Impress Points.

Los puntos deben poder obtenerse mediante:

* participar en challenges
* recibir votos competitivos
* quedar en posiciones altas
* Top 3
* ganar challenges
* participación y actividad válida

Pero ganar debe tener mucho más peso que simplemente recibir likes.

NO convertir seguidores directamente en puntos ni permitir que una cuenta con muchos seguidores gane automáticamente.

Crear niveles de estilo, por ejemplo:

NEW FACE
RISING STAR
FASHION ICON
STYLE ROYALTY
SUPERSTAR
LEGEND

El sistema debe poder ampliarse posteriormente con más niveles.

Los puntos y niveles deben calcularse automáticamente y guardarse en la base de datos.

7. FOLLOWERS NO DEBEN DECIDIR EL GANADOR

El número de seguidores NO debe equivaler directamente a votos.

Una persona con muchos seguidores puede tener mayor visibilidad, pero eso no significa que sus seguidores puedan convertir automáticamente esa popularidad en una victoria.

Diseñar la arquitectura para que posteriormente podamos utilizar un sistema de puntuación normalizado si fuese necesario.

8. TEMPORADAS MENSUALES

Además de los Weekly Challenges, quiero una competición mensual.

Ejemplo:

OCTOBER — HAUNTED FASHION SEASON 🎃

Cada semana existen diferentes challenges.

Al terminar el mes, el sistema calcula automáticamente el rendimiento acumulado de los participantes y determina:

👑 MONTHLY WINNER
🥇 Monthly Top 3
🏆 Weekly Winners

Quiero que una persona pueda ganar una semana y aun así no necesariamente ganar el mes. El rendimiento consistente debe importar.

Para Halloween, la estética mensual puede transformarse temporalmente en una mezcla ORIGINAL de glamour oscuro, cute horror, fashion dolls, Monster High energy y Bratz attitude.

IMPORTANTE: esto debe ser un sistema de temas visuales configurables. En el futuro podremos cambiar Halloween por Navidad, San Valentín, verano, futurismo, etc., sin reconstruir la aplicación.

9. FOUNDER

Crear un rol especial para el creador de la plataforma.

Mi cuenta debe tener permanentemente:

👑 FOUNDER

con badge visual exclusivo.

El Founder debe tener:

* perfil oficial
* badge permanente
* capacidad administrativa para crear/gestionar challenges
* capacidad para configurar temporadas
* acceso a funciones administrativas futuras
* identidad visual especial

NO quiero simplemente recibir puntos artificiales ni manipular las votaciones.

Founder debe ser un rol independiente de la clasificación competitiva normal.

Todo lo anterior debe estar diseñado para funcionar automáticamente.

No quiero depender de mí contando votos cada semana.

El sistema debe manejar automáticamente:

* apertura de challenge
* cierre de submissions
* periodo de votación
* cierre de votación
* validación de votos
* cálculo de resultados
* ranking
* Top 3
* ganador
* distribución de Impress Points
* actualización de niveles
* publicación del resultado
* actualización de estadísticas
* cierre de temporada mensual

La arquitectura debe permitir posteriormente añadir notificaciones automáticas.
